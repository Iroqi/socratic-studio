# 制品写作与素材能力

> 写作层负责"写什么、怎么讲"，素材层负责"用什么表现语言讲"——它们是同一件事（写这一页制品）
> 的两端，所以住在同一份文档里。**两层都不套模板**：页面结构与呈现方式由 Agent 依据内容决定。
> UI 是 Graph 和 Progress State 的投影，不是新知识源，也不是独立的学习模式。
> 素材的**来源是能力，不是制品类型**。
> **讲解顺序：** Graph 已按 `depends_on` 拓扑排序，其 `concepts[]` 顺序是默认
> 顺序；认知路径明确更优时可局部调整，但**不得违反 `depends_on`**，且需向学习者说明调整意图。

## 1. 从认知路径出发

写 HTML 之前先定这条路：从哪个**问题或困惑**切入、中间有几个**转折**（一次比较、一次预测、一次操作）、
结尾要带走哪句**可复述的结论**。页面结构是这条路径的影子——不要先选一个骨架再往里填内容。

## 2. 内容层语义

写制品时优先把 Graph 的 concept 字段用起来（字段全集与语义见 `protocols.md`「字段说明」）——
**知识侧只有一个来源：Learning Graph**。

**视觉表达**不属于任何一组数据源：它是你声明**语义角色**（流程、因果、结构、比较、数据、动态过程）
的方式，不指定固定图片槽。

## 3. Learning-first 写作原则

**分层适用。** 这一节里有一条对**所有**制品无条件的底线，其余是可随制品尺寸放宽的推荐项。
不要因为"制品很小、很临时"就连底线一起放弃；也不要拿成品的完整标准去卡一个 40 行的即时模拟器。

**底线（无条件）：**

- 制品必须在**没有音频、没有自动播放、没有引导播放**的情况下仍然成立。正文不要依赖
  “下一帧才出现”的上下文。
- 不能出现**只有作者知道怎么用**的交互：任何可点/可拖/可输入的东西，页面上要有一句
  说明它是什么、点完会发生什么。
- 不能把**唯一的信息**放在动画里。动画只能是已有信息的增强，不是它的唯一载体。

> 底线不随尺寸变化。一个 30 行的模拟器也必须满足这三条——否则它在别人那里就是坏页面。

**推荐（按尺寸取舍）：**

- 让核心信息本身可滚动阅读。
- 让图、文字、交互自然进入内容流。
- 将 self_check/predict/choice 用于认知转折，不要把所有交互退化成结尾测验。
- 交互要有**真实用途**：预测、判断、比较、操作、反思、练习。没有 authored assessment 就不硬加选择题。

> 推荐项在**小尺寸交互物件**上可放宽：如果这一段的目的是"亲手拖一下感受弹簧阻尼"，
> 那它的价值就在那个手感里，不必再配可滚动的完整讲义。判断依据是**这段教学的认知动作**
> 需要什么——需要读的东西写得能读，需要玩的交互做得能玩，不要两边都只做一半。

### 3.1 交互深度分级（按概念类型选，不要一律停在第一级）

| 深度 | 学习者在做什么 | 适合的概念 |
|---|---|---|
| 调参试错 | 改一个值，看结果怎么变 | 有可操作机制的概念（参数、阈值、边界） |
| 预测验证 | 先猜，再公布真实结果 | 有明确因果、能产生预期偏差的概念 |
| **建构** | 自己搭出结构 / 排定顺序 | 结构性、系统性知识 |
| **设计** | 自己定目标与约束，做完自评 | 技能类、项目类内容 |

**「项目化」的本质就是把交互推到后两级。**

**深度 ≠ 炫技。** 这张表量的是**学习者在做什么**（调参 / 预测 / 建构 / 设计），不是**效果多花哨**。
下面这些东西**不算深度**，只是在挤占注意力，默认不要：

- 不承载任何信息的入场动画、粒子、光效
- 为了"高级感"加的缩放 / 悬浮特效 / 3D / Dashboard 外壳
- 同一份信息的第二张、第三张重复图
- 纯装饰的分隔、图标、渐变

判据还是那一条：**这段的认知动作需要什么**。需要动手就让人动手（深），不需要就老实静态——
**"多给点交互"和"多给点动画"都不是默认值。**

## 4. 素材总原则

素材是 Agent 在写制品时可以调用的能力。选择哪种实现只取决于**内容需要什么**，与制品能否成立无关——制品在没有素材时也必须是完整的。

**来源是实现细节，不构成 Artifact 类型。** 素材可以来自内生 HTML/SVG/MathML，也可以来自其他 Skill、图像/视频生成、
视觉理解、文件处理或用户提供的媒体。得到素材后，Agent 再决定直接展示、嵌入制品、跨 Skill 继续加工、持久化或丢弃。

**能力有两个方向，别只用一半。** 输出向生成素材（图像 / 视频 / SVG / 音频）；输入向读学习者的
手写照片、草图、录音——拿到的不是素材而是证据（见 `runtime.md`「EVALUATE」）。

**素材细节不足时的分寸：** 不影响理解（配色、布局、要不要加个标签）→ **合理假设，直接做完**，
不要问；明显影响理解（画哪条关系、用哪份数据）→ **只问那必要的一句**。**不要为了把形式问完整而
连续追问**——素材是教学的副产品，不该反过来打断教学节奏。

## 5. 视觉表达：判据与纪律

需要视觉时**先说明语义角色**（流程、因果、结构、比较、数据、真实参考、动态过程），再选实现——
「语义角色 → 首选实现」的对应表在 §6。本文档只守一条：视觉不绑定固定尺寸或
固定布局槽，呈现由内容需要决定。

**判据说"该有"；怎么画得让人一眼看懂、静态图怎么组织、画完看着不对怎么查，
是 §6–§9 的事。**

### 5.1 视觉与数据：禁令与正向要求成对

> **数据不存在就别画；数据存在就必须用起来。** 两端都是硬要求，只做其中一端都不合格。

这条纪律有两个方向，成对成立、缺一不可：

**方向一 · 禁令（防伪造）：视觉只在有真实语义数据时生成，没有就老实用文字。**
没有 `depends_on` 就不画依赖图，没有可信数值就不画坐标图——**画了不存在的东西就是编造，比不画更糟**。
"画出来的必须真"的具体标准见 §5.2。

**方向二 · 正向要求（防偷懒）：Learning Graph 里已有的数据，必须出现在制品上。**
只有禁令时，保守的执行者会整体退回纯文字，因为纯文字永远不违反禁令。所以补三条正向判据：当前要讲的
内容命中下表任一条，**这一轮就默认产出对应视觉**，没有就是不合格——命中即"要不要做"的答案，不再把它
推回 §4 的文字优先去二次裁决（§4 管的是"做多大、用哪种实现"，不是"要不要做"；默认姿势见 `runtime.md`
「制品生成判断」）。

| 概念具有什么 | 制品上必须有什么 | 数据来源（都在 Learning Graph 里） |
|---|---|---|
| 概念之间**存在关系**（依赖 / 包含 / 对立） | 结构图（概念图：节点 + 有向边） | `depends_on`、`confused_with` |
| 概念有**空间 / 几何 / 数量**含义 | 图形——不是列表，不是文字描述 | `examples` |
| 概念有**过程**（见 §5.3） | 动态呈现 | — |

### 5.2 不许编造（数据 / 关系 / 地理）

§5.1 说"数据不存在就别画"；这一节说另一端——**画出来的东西必须真**（视觉诚实性）。
教学制品里的假信息会被当成知识记进去，代价比不画高得多。

**数据：**

- 不得编造数据，不得改变数据含义。
- **不得使用误导性的比例**：坐标轴不从 0 开始时必须写明；面积/长度视觉不能与数值不成比例。
- **不得隐藏重要单位**。
- **不得把估算当事实**：估算出来的数字要标明是估算，或干脆不落到图上。

**关系：**

- 不得凭空创造关系（没有 `depends_on` / `confused_with` 数据就不画依赖图或混淆图）。
- 不得把推测表现成事实（"可能是 A 导致 B" 不能画成一条实线箭头）。
- **不得删除会改变含义的重要关系**——为了让图更好看而省掉一条边，等于改了知识结构。

**地理：**

涉及真实地理时，用可靠地理数据，**不编造地点、边界、路线**。拿不准就退回文字描述位置，
不要"大致画一个"。

### 5.3 什么时候**必须**有动态呈现（正向要求）

判据的家在 §5.1 方向二（只列禁令，执行者会整体退回静态文字）；本节给的是"动"的命中条件，
它反对的成品特征见 §5.4。

**判据：如果这一段的认知动作本身是「随时间变化的」，就必须有动态呈现。**

> **「该动的地方不许用静态糊过去」与「不该动的地方不许炫技」是同一条纪律的两面**——
> 交互/动画强度的默认值在 §3.1，这里只覆盖"动"成为**义务**的情形：不命中下面四条判据之一
> （或 §5.1 三条正向判据之一）时，动与静都不默认。

满足以下任一条，静态呈现就是不合格的：

| 情形 | 静态做法（不合格） | 应有做法 |
|---|---|---|
| 过程有**先后顺序**且顺序本身是信息 | 把过程一次性铺成表格/列表 | 按时间轴逐步演进（元素逐个出现/位移/变色） |
| 有**比较**且比较是逐位的 | 直接给出结论「1 < 10」 | 让两个对象对齐、逐位亮起、在分歧处分开 |
| 有**状态变化**（排序中、指针移动、变量改写） | 只给初始值与最终值 | 展示中间态，让学习者看到"正在发生" |
| 有**因果链** | 并列写出原因与结果 | 让因先发生、果跟着出现，视觉上连起来 |

> **与底线的边界（重要）：** 「不能把唯一信息放在动画里」仍然成立。做法是让**动画承载
> 过程**、**文字承载结论**——学习者跳过动画也能读到结论，但看完动画才真正"看见"过程。

### 5.4 反模式：课件化

以下特征出现两条以上，基本可以断定做成了课件，应重做：

- 页面主体是「若干 `<section>`，每节一段说明 + 一个静态代码块/表格」
- 动画/过渡只用于**入场**（fade-in），不承载任何过程信息
- 所有交互集中在结尾（"学完了，来测测"），中途没有可操作/可观察的东西

## 6. 按语义选实现

**先过判据（要不要上这个素材），再查语义表（这个语义用什么实现）**——顺序不能反。

判据只有一条：这个素材是否让这段教学更有效，代价是否值。

两类实现各有分工。**内生**（SVG、MathML、CSS/Web Animations、HTML、JS）结构可控、即时可改，
适合结构 / 流程 / 数据与可交互内容，代价是全得自己写。**外部 / 多模态**（图像生成、视频生成、
视觉理解、文件转换、其他 Skill）换来真实感、复杂画面、现成素材和本应用不该自己实现的能力，
代价是**调用成本、生成延迟、能力不可用/不可控、跨工具协调成本**。结构化内容默认走内生；外部能力
能显著提高教学效果或降低实现成本时就主动调用。

> 能力不可用或生成失败时的退法见 §10.2。

| 语义角色 | 首选实现 | 说明 |
|---|---|---|
| 结构 / 流程 / 因果 | 内联 SVG | 手写，体积小、可动、即时渲染 |
| 比较 / 并排对照 | 内联 SVG | 同一画布内组织 |
| 数据 / 坐标图 | 内联 SVG 或 Canvas | 由真实数据算出坐标，不画示意图充数 |
| 公式 / 推导 | 原生 MathML | `<math display="block">`，**不要**引 KaTeX/MathJax CDN |
| 概念依赖图 | 内联 SVG | 节点 + 有向边，数据来自 Graph 的 `depends_on` |
| 真实参考照片 / 写实场景 | 图像生成或其他图像 Skill | 先确认当前环境可用能力；不把固定工具名写死 |
| 动态过程 / 演示 | CSS / Web Animations，或视频生成能力 | 能内生表达就优先内生；复杂写实或连续镜头需要时调用视频能力。**认知动作随时间变化的段落必须动态呈现**，判据见 §5.3 |
| 需要编辑、提取、转码或理解已有媒体 | 其他 Skill / 多模态能力 | 让外部能力承担其擅长的处理，不在 Socratic Studio 内重复实现 |
| 层级 / 分类 / 包含关系 | 内联 SVG 树状图 | 与「结构」的区别：结构讲**组成**，层级讲**上下位** |
| 编年 / 事件先后（内容本身是时间线） | 内联 SVG 时间线 | 这里的时间线是**内容本身**（事件先后），不是动画时钟 |
| 真实地理 / 位置关系 | 地图（须用可靠地理数据） | 宁可用文字描述位置，也不要画错（见 §5.2） |

**不要机械照表选。** 上面的判据先过，这张语义表只是**候选清单**——一种形式不能自然表达这份
信息，就换一种，别硬套。反过来，表里有合适的形式但这段内容并不需要视觉时，也别为了用表而用。

## 7. 让人看懂：动手前先做六个动作

§5.1 的判据管"**该不该画**"，语义表管"**画成什么形式**"，这一节管第三件事：**怎么让人一眼看懂**。
都是可执行动作，不是审美偏好。

1. **先用一句话写出"这张图让人看到什么"。** 写不出来，说明该画什么还没想清——回 §5.1 的判据重新判断。
   这句话之后也是你自查的标尺（§17）。
2. **一次只突出一件事。** 想同时讲清三处关系，就画三张小图或分步揭示，不要全塞进一张。
   元素越多，"值得看"的那个越被稀释。
3. **对比只用一个通道。** 要让人看出"A 和 B 不同"，就只改**一个**通道：颜色、大小、位置、形状，
   四选一。同时改三个，读者分不清到底是哪个在表示差异。
4. **重要层级要占"三处不同"。** 主元素在**大小**、**位置**（是否压在视觉重量上）、**颜色深浅**上
   同时不一样。只改一处通常不够——这正是"看着都对，但抓不住重点"的常见原因。
5. **标注就近，不要图例兜底。** 标签贴在被标的东西旁边。靠"图例 + 颜色"对照会强迫读者来回扫视，
   认知负担翻倍；图例只在元素样式完全一致、且数量多时才划算。
6. **删到删不动。** 每条线、每个装饰都问一句"删掉会损失什么信息"，答不出来就删。
   **留白不是浪费**——挤在一起时，结构会被噪声淹没。
   （数值图的零基线、刻度、单位属于另一件事，见 §5.2。）

## 8. 静态视觉的实现骨架

结构图、概念图、坐标图、对照图这类**不随时钟演进的图**走这一套：**分层预置 + 数据 → 布局的纯函数**。

```js
// ① 分层预置（写在 HTML 里，不用 JS 造层）：后画的层盖住前面的
//    <g id="L-axes">  <g id="L-edges">  <g id="L-nodes">  <g id="L-labels">
// ② 布局是纯函数：数据 → 坐标。
//    不要手写坐标常量——改一个数据点就要重排全部，手写常量必然漏改。
const W = 640, H = 320, R = 26;
const PAD = R + 18;         // ← 安全边距**由半径推出**，不要拍脑袋写个 24：
                            //   PAD < R 时首尾节点会被 viewBox 裁掉一截
const xAt = (i, n) => PAD + i * ((W - 2 * PAD) / Math.max(1, n - 1));
// ③ 值 → y：先定域再定值。域不从 0 起就必须在图上写明（§5.2）
const yAt = (v, lo, hi) => H - PAD - (v - lo) / ((hi - lo) || 1) * (H - 2 * PAD);
```

**骨架落地时必须做对四件事**（拿概念依赖图验证：数据源就是 Graph 的 `depends_on`，不是编的）：

- **分层**：边 / 节点 / 标签各归一层，边先画、压在节点下面——层的先后就是视觉层级。
- **绕开节点的曲线**：连线用拱起的二次贝塞尔（`Q`，控制点抬到节点上方），不用直线穿过去——
  连线压在节点上是"删噪声"最常见的一种。
- **就近标注**：标签居中贴在节点正下方，不靠图例（§7 动作 5）。
- **不写死一个颜色**：全程 `currentColor` + 透明度；宿主给的是一张固定的白纸，没有主题可继承。

下面三条 delta 换三种语义，**骨架仍是上面那一套**（分层预置 + 数据→坐标的纯函数），只列差异。

### 8.1 语义一：坐标图（数据 → 比例长度）

与上面骨架同一套（分层预置 + `xAt`/`yAt` 纯函数），差异只有三点：

- **定域**：y 域必须包含 0——长度 ∝ 数值才不骗人（§5.2）。真实数据都 > 0 且差异很小时，
  宁可不动 y 域：把 0 画出来，差异自然显现；**绝不为"显眼"截断基线**。
- **多一层轴 / 网格**：零基线永远画出来，刻度就近标在 y 轴上（不靠图例）。
- **数据形状**：`{x:'第1周', v:0.32}` 这样的数组，来自真实数值（Graph 或可信来源），不编造。

### 8.2 语义二：对照图（一个通道讲清差异）

差异在**怎么表示"谁更好"**（§7 动作 3、4）：

- 两个对象先靠**位置**分"谁是谁"，"谁更好"就只再走**一个通道**——这里用"填充实/虚"：
  被选项 `fill: currentColor`，未选项 `fill: none` 加一档低透明度，只改这一处。
- 被突出的项占**三处不同**：数据更高 + 实填充 + ✓ 徽标。两边都加 ✓、都加粗等于没突出。
- 布局从"均分一行"换成定宽柱居中：柱高 = `(v / maxV) * plotH`，`maxV` 取整域上限；
  标签就近放柱顶上方。

### 8.3 语义三：状态机流转图（带转移标签的有向边）

差异在**边语义**：概念依赖图的边是无标签曲线，这里每条边要说清"什么条件触发流转"。

- 数据是 `[from, to, 触发条件]` 三元组；转移标签就近放在边的中点，不靠图例。
- 边的起止从圆心缩到圆边缘（`±R`），相邻状态直接连线即可；**回退边**（从右向左）画成
  下方弧线避免与正向边重叠；箭头用 `<defs><marker>` 定义（`fill="currentColor"`），
  所有边挂 `marker-end`。
- 起点单独标"起点"徽标 + 更深填充——是"重要层级占三处不同"的一种做法。

**这三条 delta 都不是模板**——看它们怎么把各自那类信息变成画面，具体数据、节点、触发词由内容决定。

## 9. 画面做出来了但不对：症状 → 修法

以上都是"还没开始画"。这一节管**画完了，看着不对**——按症状查。**能力不可用 / 没做成**是另一回事，
见 §10.2。

| 症状 | 常见原因 | 修法 |
|---|---|---|
| 元素全塌到左上角，像"内容跑到画布外" | CSS `transform` 覆盖了 SVG 的 `transform` 属性 | SVG 位移一律走 `setAttribute('transform', …)` |
| 位置没写错，但内容缩成中间一条带 | SVG 写了 `height:100%`，客户区高度与 viewBox 比例不一致 | `width:100%; height:auto; aspect-ratio:<viewBox 宽/高>` |
| 文字被裁掉 / 溢出容器 | 容器固定宽高，而文本长度随内容变；SVG `<text>` 不会自动换行 | 文本层改用 HTML；或按**最长**标签预留宽度，别按平均值 |
| 看着挤或散，结构抓不住 | 每个元素的坐标各写各的，没有统一栅格 | 定一个 `PAD` 常量，所有坐标从它算（§8 ②） |
| 两个东西看不出差别 | 只差一点点颜色 / 大小，或同时改了多个通道 | 换一个**通道**（位置或形状），或把差值拉开到一眼可辨（§7 动作 3） |
| 动画看不清在发生什么 | 一步动了太多元素，或速度太快 | 一次只推一个认知动作；关键中间态要停够时间 |
| 位移是"瞬移"、看不到过程 | 同一次同步执行里连设两次位置；浏览器只认最终值 | 先设起点，**两帧之后**（`requestAnimationFrame(() => requestAnimationFrame(…))`）再设终点 |
| 图上有的地方糊了 / 看不见 | 颜色写死 | 用 `currentColor` + 透明度画在宿主的白纸上（§8「不写死一个颜色」） |
| 图和图例对不上 | 颜色/形状映射在 JS 和 CSS 里各写了一份 | 映射表只定义一处，画和标注都从它取 |

## 10. 设计定位与能力分级

采用混合模式:

```text
对话: 理解目标 / 解释 / 追问 / 开放式推理
UI:   选择 / 操作 / 反馈 / 状态展示
状态: Learning Graph + Progress State
```

不要把每条消息都改造成 UI。只有当 UI 能降低选择成本、表达状态变化，或让用户直接操作一个模型时才生成 UI。
**从轻到重**：文字 → 一个原生交互物件 → 一个主视觉 → 落盘制品；能用轻的别用重的，场景到形式的映射见 §11。

### 10.1 表现形式的能力分级

按当前会话可用能力选择最高等级，不把更高等级当作前置依赖:

| 等级 | 能力 | 失败时 |
|---|---|---|
| L0 | Markdown/文字问答 | 始终可用的最终兜底 |
| L1 | 原生问题控件（`ask_user_question`）——平台渲染的真选项，作答作为工具结果直接回到对话 | 退回 L0 短编号列表，并如实说明改用文字（见下）；**不要**假装调用过 |
| L2 | 内联 HTML/SVG/Canvas 视觉 | 用静态 SVG、Mermaid 或文字步骤 |
| L3 | 宿主回传/追问桥接 | UI 只做本地展示，不要求模型立即响应 |
| L4 | 可选的图像、视频或插件能力 | 跳过该增强，缺素材处用一句文字说明，不阻塞主循环 |

**它的形状就是你能用的形状：** 平台控件如实表达"选一个 / 选多个 / 附加一句自由文本"。
表达不了的结构（排序、分桶、拖拽建构）**不许硬塞成选择**——那等于误报学习者做了什么，比降级更糟。
退回让学习者**用自己的话产出**该结构（"把这三步按顺序写出来"）。

**怎么把 teaching 坐标带上：** 控件本身只有 `id` 与选项，没有 concept 概念。**把坐标编进 `id` 和选项标签**——
例如 `id: "closures:q_var_capture"`，选项标签写"共享同一个绑定"而不是"A"。这样证据落进对话时自带
定位，而**不需要**给平台工具加字段。

**能力不在时的走法（别装作调用过）：** 万一该工具不在当前工具表里，退回 L0 短编号列表，
并把"我改用文字问你"如实说一句（口径同 §10.2 第 4 步）。**绝不许声称用了交互控件而实际是打字列
选项**——那既骗了学习者，也污染了"这条证据是怎么来的"。

**降级规则:** 只为核心学习动作保留文字兜底；可视化、动画、图片和插件失败时不反复重试，不声称已经生成或保存了结果。

### 10.2 素材能力不可用时的降级

上面那张表管**整页表现形式**的等级；这一节管**单一素材能力**（图像/视频/动画/插件）失败后的走法。

两个触发场景：**选定的能力不可用**（如环境没有图像/视频生成），和**生成失败**。
沿阶梯逐级下退，前一级够用就退到那一级为止；**不跳级，也不在不必要时停在最低级**
——停在最低级通常是忘了判断。

1. **换最接近的现有能力**（两场景通用）——找能表达同一语义的另一能力：
   图像生成不可用但内联 SVG 能表达，就手写 SVG；动态/交互视觉做不了，就退成静态图解
   （SVG 或生成图）。
2. **降低复杂度**（换能力也覆盖不住时）——把动态降成静态图示，把多步动画降成一张结构图；
   静态图解也表达不了，才退纯文字。
3. **保留核心信息**（两场景通用）——降级的是表现形式，不是内容；这一步要讲的东西一句不少。
4. **如实说明实际限制**（两场景通用）——告诉学习者"这一步改用文字讲"，
   **但不要报工具名、错误码或编排细节**。

**生成失败时不重试、不阻塞主流程。** 第 4 步的"说明限制"和"不暴露工具细节"不矛盾：
前者是**教学上的诚实**（别让学习者以为本来就该这样），后者是**不把内部机制倒给用户**。

禁止用 generic placeholder 冒充完成度。

## 11. 选择呈现形式

| 场景 | 首选 | 不要做 |
|---|---|---|
| 目标澄清 | 2–4 个选项 | 一次询问所有背景信息 |
| 诊断选择 | 单题卡片 | 把多个独立问题塞进一张卡片 |
| 开放推理 | 文字回答 | 用选择题替代解释过程 |
| 过程/状态变化 | 步进视觉或局部动画 | 同时堆多个图和控制条 |
| 主动回顾 | 继续 / 换题 / 回顾 三选一 | 复杂日历和统计面板 |
| 学习进度 | 一张主看板 | 把内部字段摊上看板（§14） |

一个 UI 表面只服务一个当前决定。默认不加不服务该决定的搜索 / 筛选 / 工具栏（装饰类禁用的判据见 §3.1）。

## 12. 题型与证据

题型可以丰富，但它只是**输入形式**，不改变 mastery 状态机；每种题型都要映射到 concept 与
`observable_skills`。作答时把证据记全：排序题记**具体错位在哪一位**，参数操作 / 模拟题记
**操作序列与最终结果**（若落事件日志，写进 `[EVENTS]` 的 `detail`；日志可选，持久化契约见 `runtime.md` §1.6）。

选择题的干扰项要绑定已知 misconception（候选来自 `misconceptions`，混淆对象见 `confused_with`），
否则它只是一次快速检查，不算高质量掌握证据。掌握度证据的门槛、错误分类与收答形式的例外都在 `runtime.md`
（§1.2 转换事件、§2.5 EVALUATE、§5 两条硬规则），本节不另立标准。

## 13. 交互事件流水线

一次 UI 操作从发生到影响掌握状态，走的是同一条流水线：**操作 → 事件 → 评估 → 局部重渲染**。

**两条投递通道，优先原生。** 同样是"学习者点了一个选项"，到达 Agent 的路有两条：

| 通道 | 何时用 | 怎么到 Agent |
|---|---|---|
| **原生问题控件**（`ask_user_question`） | 可枚举的收答——探针、预测、练习、门禁确认 | 平台把作答作为**工具结果**直接交回；teaching 坐标编在 `id` 与选项标签里（§10.1） |
| **页面型制品**（落盘 HTML） | 需要动手操作一个模型——调参、试错、模拟器 | 下一轮由 Agent 读 DOM 状态（§13.1），或经对话窗口追问 |

**原生通道少一次竞态**（阻塞到作答为止，不存在"页面还开着但人已走神"的中间态），因此**不需要** §13.1
的 `data-*` 契约与去重/过期校验——那些是为页面型的异步观测准备的。能用原生就别自己造页面。

**事件协议。** 页面型制品的每次 UI 操作都应能映射成一个最小事件。事件由宿主/Agent 从对话回答或 DOM
快照写入当前 Runtime 上下文，不直接修改 Learning Graph。

```json
{
  "event_type": "answer_submitted",
  "concept_id": "closures",
  "question_id": "q_12",
  "interaction_type": "choice",
  "response": "B",
  "result": "correct"
}
```

**必需字段:** `event_type`、`concept_id`、`question_id`、`interaction_type`、`response`。

**`result`:** `correct` / `incorrect` / `recorded`，仅客观题经 Agent 判定后写入；开放式/主观题省略。
持久化契约见 `runtime.md` §1.6。

**处理顺序:** 校验事件完整且属于当前 question → 转成 Runtime 可读的回答与证据 → EVALUATE 判对错与
错误类型 → UPDATE MASTERY 写 Progress State（状态写入权限以 `runtime.md`「环节边界」为准）→ 生成下一张
UI 或回到对话解释。

重复提交、过期 question 或无法解析的事件应被忽略并给出可恢复提示，不得污染 mastery 状态。

**答后必须有"下一步"（硬要求）。** 学习者做完一个交互，必须能回答
"我现在该做什么"——说不清，学习者分不清"是我没做对"还是"本来就该停"，卡住感就是制品的死刑。
未作答时就要写明继续条件（按钮可先禁用，但要显示出来）；完成后给一个明确的"继续 →"入口，
并说明还有多远——别让学习者停在"做完了，然后呢"的空档里。**原生问题控件自动满足这条**：它阻塞到
作答为止，答完即回对话，"下一步"就是老师接下来说的那句话——**页面型制品没有这层保护**，必须显式写。

**原生通道不记 attempt 数。** 问题控件只回收"选了哪些"，**多次作答无法从一次返回里区分**。
需要"第几次尝试"时走两处：① 由 Agent 在对话里自己记（它看得见自己的每一轮）；② 页面型制品用
§13.1 的 `data-attempts`。不要让控件去数——那是把评分职责挪进制品的开头。

**"实时"的含义。** "实时"= 上面这条事件级流水线，不要求模型持续向 HTML 推送 token。宿主回传能力
不可用时，保持 UI 的本地展示并在正文继续提问；不要让学习 UI 依赖未确认的网络、WebSocket、后端 API、
鉴权或持久化职责——需要真正的服务端数据时，先由外部工具或后端取得，再把结果作为输入交给 Runtime。

### 13.1 DOM 观测映射

运行时不导出遥测，证据由 Agent/宿主从页面读出来。下面把这套属性补齐定义——它们是**跨制品统一的
契约**，改名或改取值就等于毁掉已经写好的页面。

**可观测交互的标注**（宿主页写 → 宿主/Agent 读，运行时**不读**）：

| 属性 | 取值 | 语义 |
|---|---|---|
| `data-concept-id` | Graph 里的 `concepts[].id` | 把这个交互映射回**概念** |
| `data-question-id` | 题目 id（如 `q_box_count`） | 映射回**具体题目**；消费侧靠它校验"是否属于当前 question"与去重 |
| `data-interaction-type` | `choice` \| `predict` \| `compare` \| `toggle` \| `explore` \| `reflection` \| `sequence` | 这次观测是什么形式的作答；序列化时对应事件的 `interaction_type` |

**作答状态标记**（运行时/宿主页写 → 宿主页读）：

| 属性 | 取值 | 语义 |
|---|---|---|
| `data-attempts` | 累计整数，每次作答 +1 | 第几次尝试。**原生 `ask_user_question` 通道拿不到这个**——它一次返回只有"选了哪些"，多次作答无法区分；要"第几次"就走页面型制品，或由 Agent 自己在对话里记 |
| `data-result` | `correct` \| `incorrect` \| `recorded` | 机械比对的结果。仅客观题写；开放式/主观题省略 |
| `data-response` | 字符串，截断至 1000 字符 | 学习者实际给出的答案。排序题记**具体顺序**，操作题记**操作序列与最终结果**——别只记一个对错 |
| `data-completed` | `'1'` \| `'0'` | 该交互块是否完成。**明确答错一律 `'0'`**（不分是否阻塞门禁）；参与型/记录型一律 `'1'` |
| `data-locked` | `'1'` | **只有答案被锁定的完成才置位**。无 `correct` 声明的 choice / toggle / explore / reflection 完成时只有 `data-completed='1'`，学习者还能改答 |

> **观察门禁是否解除以 `data-completed` 为准，不要等 `data-locked`。** 后者意味着"不能再改"，
> 是更严的条件；拿它当完成信号会让"还能改答"的交互永远不解锁。

> **不要轮询。** 用 `MutationObserver` 观察这些属性，这是运行时主动通知的唯一时点。
> 注意一个盲区：`data-completed` 从**缺省**（`undefined`）变成 `'1'` 只在首次作答触发一次 mutation，
> 在此之前该属性没有任何属性变化。只想观察「第一次完成」时，要么 `{ attributes: true }` 观察整个元素，
> 要么初始化时先读一次 `dataset.completed`，别只监听 `'0' → '1'`。

**判定口径**（`correct` / `correct_order` 都是题目自己声明的，运行时只做机械比对）：

- `choice` / `self_check` / `predict` / `compare`：**只有选项声明了 `correct: true` 时才要求答对**；
  没有任何选项带 `correct` 字段时，选出即算完成。反过来也成立——若按"声明过任意布尔"判定，
  只标了 `correct: false` 的集合会因为不存在正确答案而永不放行。
- `sequence`：作为阻塞门禁时**必须提供 `correct_order`**，缺失则拒绝提交并在控制台告警；
  非阻塞的 `sequence` 缺它时按"已记录排序"完成。
- `explore`：要求发生一次**真实的值变更**（`change` 且偏离基线），不是任意 `input` 事件。
- `reflection`：去空白后至少 2 个字符。

**交互块的内部选择器**（宿主必须写出，否则对应行为不发生）。这是运行时的契约，不是可选建议：

| 交互类型 | 宿主必须提供 | 运行时对它做什么 |
|---|---|---|
| 通用 | `.interaction-feedback` | 写反馈文案，切换 `hidden` 与 `is-correct` / `is-wrong` |
| 通用 | `.interaction-badge` | 答对解锁时去掉 `hidden` |
| 通用 | `[data-hint-action]` + `.interaction-hint` | 点 hint 按钮切换 hint 的 `hidden` |
| `toggle` | `[data-toggle-action]` | 点击切换 `data-toggled`，即算完成 |
| `choice`/`self_check`/`predict`/`compare` | 每项 `[data-choice-id="<id>"]`，id 与 `options[].id` 对应 | 挂点击判定；写 `data-selected`；答对后所有项 `disabled` |
| `explore` | `[data-explore-input]`、可选 `[data-explore-output]`、input 上的 `data-explore-initial`（基线） | 同步 output 到 input 的值 |
| `reflection` | `[data-reflection-input]` + `[data-reflection-submit]` | 提交时校验长度 |
| `sequence` | `.sequence-list`、每条 `.sequence-item[data-sequence-id]`、`[data-sequence-submit]` | 拖拽排序；提交按 DOM 顺序比对 `correct_order` |

`data-interaction='<JSON>'` 的配置**与属性在同一处**：`<div data-interaction='{"options":[…]}'>`。
**勿再写一个空的同名属性**——HTML 重复属性只认第一个，配置会静默丢失。

**接线幂等：** 每个交互块首次接线后写 `data-wired='1'`，重复调用跳过。没有这层标记，
每接一次就多挂一层 `click` 监听——点一下记成多次作答。交互块或容器**动态生成**时，
建好 DOM 后必须重新调一次接线入口。

**坏配置时不白屏。** timeline JSON 或 `data-interaction` 的 JSON 解析失败时：在控制台指明是哪个块，
该块按"无配置"处理，页面其余部分照常可用。注意代价——选项解析失败会被当成"没有正确答案声明"，
错答也能过关。写完交互块要验一遍 JSON。

**消费侧三条义务：** 这些属性只是 DOM 快照，**不是第二套 Progress State**。校验题目是否属于当前
question → 去重过期操作 → 再交给 EVALUATE / UPDATE MASTERY。重复提交、过期 question 或无法解析的
事件应被忽略并给出可恢复提示，**不得污染 mastery 状态**。运行时只做机械比对，不发明判定标准、
不计算掌握度、不暴露作答汇总。

若序列化成事件行（`[EVENTS]`，可选），字段对应：`data-concept-id` → `concept_id`、
`data-question-id` → `question_id`、`data-interaction-type` → `interaction_type`、
`data-response` → `response`、`data-result` → `result`。事件协议的必需字段见 §13 上文。

### 项目 / 游戏 / 模拟器：通用回报通道

`data-interaction` 覆盖的是**答卷型**交互。但实战项目、关卡挑战、可探索系统的状态不是
"答了一道题"能表达的——到第几关、试过几次、当前参数是什么、哪一步失败了。这类内容走
宿主提供的通用通道，制品里的脚本直接调它：

| 调用 | 作用 |
|---|---|
| `SocraticStudio.report(state)` | 上报一份状态快照（浅合并、累积）。宿主持久化，下一回合注入给 Agent |
| `SocraticStudio.emit(name, payload)` | 上报一个离散事件，如 `level_cleared` / `bug_found` / `run_failed` / `build_succeeded` |
| `SocraticStudio.getState()` | 读回当前状态；跨轮续玩时初始值来自宿主注入 |
| `SocraticStudio.onCommand(cb)` | 订阅 Agent 的下行指令，回调签名 `(name, payload)` |
| `SocraticStudio.submit(text)` | 把制品里的**产出交回会话**：宿主作为学习者发言发起一回合，老师当场接着讲 |

**产出要能交回会话。** 制品里算出来、汇总出来的东西用 `SocraticStudio.submit(text)` 交回去。
**不许写"复制到别处即可"**——那等于把"作答 → 老师当场判断"这半截回路丢给学习者手动搬运，
他多半不搬，这段产出就白做了。

`report` 与 `emit` 的差别：**state 是快照**（同一份东西反复覆盖，读方拿最新值），
**event 是流水**（发生过的每一次都留着）。"到第 3 关了"是 state；"刚才第 2 关失败了一次"
是 event。

**state 里只放客观事实**：关卡、尝试次数、当前参数、走过的路径、已发现/未发现的目标。
**不放任何评分**——`score` / `mastery_percent` / `progress_pct` / `pre_score` / `delta`
一 类字段出现在制品 `data-*` 或 state 里即违规（`protocols.md` Invariant 4 违规指纹 ②）。
算不算概念错误、算不算掌握、下一步怎么走，是 Agent 的判断，不是制品的。

> **为什么必须读回**：`runtime.md` §3 游戏化阶段已把它写成硬要求——「连续几次失败 → 一次
> conceptual error 的证据；顺利通关 → Applied 级证据。**不读回等于白玩**」。

> **两边的时序**：制品回报**不要求回合正在进行**。学习者关掉对话去玩，回报会先落盘；
> 下次他开口说"我过到第 3 关了"，Agent 调 `read_artifact_evidence` 就能拿到。
> 反过来，回合进行中收到的回报会直接进会话，Agent 本回合内即可读。

> **制品已关掉时指令送不到**：`onCommand` 只对还开着的页面有效。Agent 下发指令后若制品
> 已关闭，应退回对话继续讲，**不要装作学习者已经收到**。

> 本契约的可执行实现见 Web 应用版 `web/socratic-runtime.js`（含接线幂等、证据写入与去重键），
> 以及 §13 的宿主侧消费路径。

## 14. 看板与状态投影

看板是**只读投影**，至少包含: 当前 concept 与学习目标、学习阶段的自然语言描述、待处理的一个动作、
已观察到的证据摘要、下一步建议。对外措辞用自然语言，不摊内部 state block（口径见
`runtime.md`「State Block 与 Learner View」）；用户主动要求调试细节时才展示内部视图。

更新来源只能是 Progress State 和已确认的事件；不在 UI 中另存一套 mastery 分数，也不让学习者拖动
进度条改变掌握状态（`protocols.md` Invariant 1 与 4）。

## 15. 资源契约

资源没有统一的"必须落盘"要求：可以是当前消息里的内联结果、学习者上传的素材、或已落盘的制品
（本应用把制品记在 `artifacts/` 与 `manifest.json`，素材记在 `uploads/`）。只有 HTML 要引用本地资源时才用宿主可解析的相对引用，不依赖绝对路径或
`file://`。保持素材自然尺寸/比例，不为统一槽位裁切。

## 16. 外部能力与插件

图片、视频和其他 skill/plugin 在本应用里**都不存在**——能用的增强只有学习者自己上传的素材。
是否存在（`main.md`「表现能力」）、值不值得用（§4「素材总原则」的判据、§6 的语义表）、
失败后怎么走（§10.2）都已在前面立了家。本节只补一条它们不管的：
**引用素材要记录来源和用途，但不要把内部机制暴露成学习流程的必经步骤；一次只用最有价值的一项增强**，
避免把学习主线变成工具编排。

## 17. 生成后的快速自查

**生成完视觉后自查一遍的清单**（不落盘、不是流程门槛）。每条只问一句，判据在各节里：

- 核心内容表达了吗？（§7 动作 1）
- 结构 / 关系正确、关键关系没漏吗？（§5.2「关系」）
- 数据准确吗？（§5.2「不许编造」）
- 是不是过度复杂？**删元素比加说明更有效**（§7 动作 6）
- 动效/交互是承载认知动作还是只为好看？只为好看就删。（§5.3 判据 + §3.1 默认值）
- 没有音频、没有自动播放时还能读懂吗？（§3「Learning-first 写作原则」）
