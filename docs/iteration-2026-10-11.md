# 迭代记录 — 2026-10-11（第二十五轮）：回答本身就是界面——给内联那一档补上词汇表

上一轮：`docs/iteration-2026-10-10.md`（第二十四轮，另一扇门也是门，commit `4c79ac5`）。
本轮的起点是一句一直写在规则里、却从来没被兑现过的话。`server/rules/protocols.md:266` 的制品谱
第一行是「**内联示意 | 对话里直接渲染，不落盘** | 一个概念点 / 一次对比，看一眼就懂」——
可宿主给的内联通道只有一种：` ```dialogue `（第四轮从 courseware-studio 搬来的对手戏）。
也就是说谱上那一档**只有名字没有形状**：模型想让"并排对照"长在正文里，唯一的路是
`share_artifact` 落一个页面。那一档于是常年空转。

本轮借 OpenAI 在 2026-10-07 随 GPT-6 提出的 **Intelligent UI** 的思路来补这条缝，
但只借它的**机制**，不借它的**自由度**——理由与逐条判决见 §2、§6。

## 1. 现状盘点（先跑，再撞）

基线 `4c79ac5`（第二十四轮）上跑全部六支套件：6/6 绿，**2135 项**（web-smoke 776 / contract 281）。
探针打在真服务上（`git archive HEAD` 出的干净副本 + `SOCRATIC_ENABLE_FAUX=1`，端口 8790）。

撞出来的事实，逐字进 §4.1：

- **谱上那一档确实没有出口**。回合正文里唯一会被换形状的围栏是 `dialogue`；`markdown.js` 的围栏分支
  对其它 lang 一律 `pre > code class="lang-<x>"`。写 ` ```ui ` 的模型只会拿到一段灰底代码。
- **机制其实早就有了，缺的只是词汇**。`text_delta` → `textBlock().text += delta` → `scheduleRender`（rAF）
  → `renderChatLive` → `innerHTML = renderMarkdown(...)`：宿主**本来就在边收边重编译整段界面**，
  这正是 Intelligent UI 说的那一手的后半句（"compiler that processes the interface as the model generates it"）。
  所以这一轮不需要新流、新事件、新服务端面，只需要给这条已有的路一组**能长的形状**。
- **内联的东西照样能落进 Progress State**。`POST /api/notebooks/:id/artifact-message` 的
  `state` / `event` 两类早就在（iframe 制品用），落进 `progress.artifact_state[artifactId]` /
  `artifact_events[]`，下一回合由 `prompt.mjs:261/275` 注入，`read_artifact_evidence` 也读同一份。
  **内联控件复用这条通道就够，服务端一个新字段都不用加**（探针 A/B/C 见 §4.1）。
- **规则已经没有地方放新词汇**。`loadRulesText()` 实测 64,962 / 上限 65,000（`test/run.mjs:1175`），
  余量 38 字符——` ```ui ` 那一整套语法不可能塞进 `server/rules/`。这直接决定了实施形状：
  **词汇表住在 `server/prompt.mjs` 的 `APP_ADAPTER`**（同一条注入路，但不占规则预算，
  且与 2026-10-04 那次把【一个孔】规范放进工具层的判断同一条口径）。

## 2. 头脑风暴：候选方向一览

| 候选 | 判决 | 理由 |
| --- | --- | --- |
| 封闭四档词汇表（`compare` / `steps` / `checklist` / `calculator`），在渲染器唯一入口处编译 | ✅ 做 | 谱上那一档需要的是"能选的形状"，不是"能造的形状"；封闭才谈得上机械校验（编译过没有是可判定事实） |
| 让模型自由写 HTML/SVG 片段，宿主照 Intelligent UI 那样直接渲进正文 | ❌ 否决 | 那等于把制品的 `share_artifact` 从落盘搬进正文：多出一个能被模型伪造"看着像官方控件"的面，且"这轮放的界面编译过没有"再也无法核对。自由度的成本在这条路上是先付的 |
| 只加 `compare`（对照表）一档 | ❌ 否决 | 一档覆盖不了谱上那一行说的情形（"一个概念点 / 一次对比"），而清单与参数是"看一眼就懂"之外唯一需要**学习者动手**的两件事；两档以上才有"选错形状"这件事可学 |
| 复用 iframe 制品那一套（`window.SocraticStudio`）承载内联界面 | ❌ 否决 | 每个界面一个沙箱帧 = 每帧重画一次 iframe，正文会抖；且内联的意义就是"不落盘、不另起产物" |
| 状态只留在 DOM（勾选靠 `checked` 属性） | ❌ 否决 | 流式那一路每帧 `innerHTML` 覆盖，状态必丢——Invariant 3（客户端状态不越界）之外还直接违背本仓"凡产出具交互性的制品，其作答状态必须能被下一轮读到" |
| 状态存宿主侧 + 按 item **原文**为键，不按序号 | ✅ 做 | 清单会重排、会中途补一行；按序号存就是把"第三格勾过"赌成"第三格还是那句话"。原文当键还有一层好处：注入给模型的 `done={"先洗":true}` 直接是人话 |
| `progress` / `percent` / `score` / `mastery` 这一族做成**显式否决名单** | ✅ 做 | Invariant 4 的违规指纹①（可见面上不许有数值化学情指标）以前只靠散文禁令；散文依赖理解，名单只依赖对照 |
| 学 OpenAI 的"简单模式"：一个全局开关，真的能关掉全部 | ✅ 做 | 开关放在编译器门口（词汇表只有一个入口），才配说"关掉全部"，而不是"减少，但有些还会冒出来" |
| 编译失败时报一条 `ui_degraded` 事件，下一回合让模型读回 | ✅ 做 | 忍住不加界面这件事不能只靠自觉；可枚举词汇表让"哪儿没编出来"成为事实，事实才进得了反馈回路 |
| 新开一条 `ui_shapes` 服务端消息类型 | ❌ 撤回 | 试过一次就回滚：内联控件和沙箱制品是同一族证据（学习者在界面里做了什么），开两条路以后就得记哪条读哪份，而注入与 `read_artifact_evidence` 只认 `artifact_state` 一处。复用 `state`/`event` + `ui:` 前缀即可（`server/serve.mjs` 本轮零改动） |
| 宿主扫 DOM 找 `.ui-degraded` 来发现降级 | ❌ 否决 | 那条路要能测，得先给 DOM 桩的 HTML 解析器补 `data-*` 支持——桩现在只认 id/class/type。测不了的正向钉子就是假绿；改挂在编译器的拒绝那一步上，事实与原因同一个出处 |
| 公式用 `eval` / `new Function` | ❌ 否决 | 词汇表封闭这条原则对表达式语言同样成立：手写"积项之和"分解，只认参数名、数、`*`、`+` |
| 给降级加"一键让模型重写" | ❌ 否决 | 本仓第四次投反对票（第二十/二十二/二十三/二十四轮同口径）：动数据/动正文由人与模型各拍各的，界面不代拍 |

## 3. 方案与实施

### 3.1 编译器：`web/ui-compile.js`（新增 393 行）

词汇表三份，全部导出以便契约测试对表：`UI_KINDS`（`:20`，四档）、`UI_VETOED`（`:28`，九档永不做）、
`UI_STATEFUL`（`:35`，只有 `checklist` / `calculator` 需要自报 `id`）。语法是每行一个 `字段: 值`：

- `compare`：`row: 甲 | 乙`，每行格数必须对齐、2–6 列；`head: no` 改成首列为标签列（`<th scope="row">`）。
- `steps`：`step: 这一步 | 为什么在这一步` → `<ol>`。序号是形状带来的信息，读屏天然会念。
- `checklist`：`id:` + `item:` 若干。重复原文直接拒绝（`:232`）——勾选态按原文存，两行一样就分不清勾的是哪一行。
- `calculator`：`id:` + `param: 名 | 默认 [| 最小 | 最大]` + `formula: 输出名 = a * b + 常数` + `unit:`。
  参数名允许汉字（`UI_IDENT`，`:254`）：`param: 人数 | 8` 读起来就是那句人话，逼模型写 `people`
  只会让中文课上的滑杆挂个英文小抄。想表达"少一个"就把常数写成负数——没有减法、除法、括号、函数。

状态侧（`:48` 那份 `Map`）编译时**读**、交互时**写**，`spec`（参数与公式表）也存下来：滑杆一响就要重算输出，
不存就得把 JSON 塞进 `data-*` 再解析一遍，多一条能写坏的路。
`compileUiBlock(lines, partial)` 的三条出口：`{html, shape}` / `{html, degraded}` / `{html, pending}`，
所有失败路径都走同一个 `fail(why)`（`:376`）——**partial 时一律不说"编不出来"**。这不是宽容，
是流式的必然：逐 token 到达时 `kind: c` 是 `kind: compare` 的前缀，此刻报未知档，
模型会收到一条自己没犯过的错。

### 3.2 渲染器接线：`web/markdown.js`（+32/−14）

编译入口只放在渲染器自己的围栏分支里（`if (/^ui$/i.test(lang))`），因为**正文每一块都从这一道过**，
流式那一帧帧重画走的也是同一条路；多一个入口就多一条"这条路上没人校验"。
`renderMarkdown(src, { partial })` 新增 `partial`，两个判据分开算：`closed`（围栏闭合了没有）
与 `growing = partial && !closed`（`:131`，还会再长）。这个区分是 §5 那枚 bug 的落点。
另加一条防抖：只打出开围栏那一行、正文还没到时不摆空块/占位（闪一下就是抖）。

`escapeHtml` 的定义搬去新的 `web/escape.js`（15 行）——`markdown.js ⇄ ui-compile.js` 会成环，
而 `markdown.js` 继续在文末 re-export 它，`app.js` 那侧的 import 一字不改。

### 3.3 宿主接线：`web/app.js`（+221/−6）

- `renderChatLive(turn, force)`（`:1802`）：`turn_end` 与 `endTurn` 用 `force=true` 那一刷（见 §5-1）。
- `handleUiDeskEvent(evt)`（`:2966`）：台面节点上的委托监听接住勾选与滑杆——控件是字符串拼出来的，
  挂不上 `onclick`。两条都转发 `{type:'state'}`，`artifactId = ui:<id>`（`UI_PREFIX`，`:2912`）。
- `reportUiDegraded(reason, lines)`（`:3030`）：按「原因 + 围栏第一行」去重后转投
  `{type:'event', name:'ui_degraded', payload:{reason}}`。
- `hydrateUiState(notebook)`（`:3007`）：只在**真换了一本**时清 Map 与降级账、再从
  `progress.artifact_state` 里那些带 `ui:` 前缀且 `uiKind` 属于 `UI_STATEFUL` 的键续回来。
  两道筛子缺一不可（少前缀那道会把真制品的账续进来，少 `uiKind` 那道会把一件小游戏的 `score`
  当成"某个清单勾过什么"），这一点是被变异测试逼出来的，见 §5-4。
- 「只要文字」开关：`#uiToggle`（`web/index.html` 一颗图标键），偏好落 `localStorage['socratic-ui-mode']`，
  `applyUiMode`（`:3047`）同时更新 `aria-pressed` 与 `title`。没开着学习时不重画台面。

### 3.4 提示侧：`server/prompt.mjs` `APP_ADAPTER`（+38 行 / 1,528 字符，规则零字符）

新增一节「内联界面：回答本身就是界面」（`:101`）：四档表 + 三条硬规矩（有状态的两档必须 `id`；
公式词法；`progress` 那一族被否决且 checklist 只记"勾了没"不记"勾对没"）。
但真正想让模型学的是那一块**克制**：

> **不需要就一个字都不要加。** ……一轮正文里最多放一个界面；放两个以上通常说明你在装饰而不是在讲。

以及"开放式提问仍走 `ask_user_question`，不许用 `checklist` 冒充提问"（它只回收勾选，不阻塞回合），
和"看到 `ui_degraded` 就改回写文字，别同一种写法一回合试两遍"。

### 3.5 样式：`web/styles.css`（+56）

22 条 `.ui-*` 选择器规则（16 个类名），颜色一分钱没新花：底全部 `var(--surface-2)`，强调只借现成的
`--accent` / `--accent-ink` 那一对。占位那一格刻意没有进度条、没有百分比、没有任何数字

## 5. 实施与验证过程中翻出来的（原设计里没有）

1. **收尾那一刷被 `dirty` 吞掉了**（真 bug，写测试时撞见）。`turn_end` 的注释本来就写着"先记 settled 再刷，
   未闭合的围栏要当场降级"，可 `renderChatLive` 的循环条件是 `!b.dirty → continue`：流式那一路的 rAF
   早已把这块刷成占位并清掉了 `dirty`，于是收尾那一刷**什么都不重画**，"正在把这个界面长出来…"
   一路挂到页面关掉。修法是 `renderChatLive(turn, force)` + `turn_end` / `endTurn` 用 `force=true`。
   **注释里写了顺序要紧，不代表代码真的守得住**——这一条现在有 m9/m10 两枚钉。
2. **"没闭合"与"还会再长"不是一件事**。原先渲染器把 `partial` 直接当 `!closed` 传给编译器，
   于是终态里未闭合的围栏继续走"还在写"那条路。分开算之后多出两个此前没定义的格子，都得有说法：
   终态且未闭合 = 写坏了（当场降级）；未闭合但内容合法 = 照形状编译（少一个结尾围栏不是写坏了）。
3. **四条假绿**，各补一枚钉：
   - m4（重复 `item` 不拒）：原测试只验"按原文键续状态、重排不认错"，从没喂过两行一样的。
   - m20（`checklist` 不再要求 `id`）：`degraded` 变成 `undefined` 而 `Boolean(undefined)===false`
     看着该红，可详情里 `JSON.stringify(undefined).slice` 直接抛 TypeError，套件**崩**而不是红——
     红与崩是两件事，详情参数不许假设字段存在。改成 `String(r.degraded)` 后正常红。
   - m22（去掉 `ui:` 前缀那道筛子）：按 id 读**读不到"多进来一个不该有的键"**——键名被
     `slice(UI_PREFIX.length)` 削成 `e-1` / `p1` 这种四不像，按原名查反而返回 null。
     于是给编译器加了 `uiStateIds()`（`:74`，唯一的用处就是让"账面"可查），钉"续回来的只有 ok1"。
     **这一枚也顺带证明：为了可测而加的那一个口子，比为了好看而加的三个口子都便宜。**
   - m24（去重键退化成常量）：原来只验"同一条报一次"，那用一条全局布尔也能过。补上"两处不同的写坏各报一条"。
4. **hydration 的三道筛子是三道，不是一道**。`ui:` 前缀认归属、`uiKind` 认是不是那两档、
   `id === state.uiHydratedFrom` 认是否真换了本子。少任何一道都会写出假状态——
   而假状态在本仓比报错更糟，因为学习者看不出自己那份勾选已经被别人的账顶掉了。
5. **DOM 桩的 HTML 解析器只认 id/class/type**。任何"渲染完再扫一遍 DOM 上的 `data-*`"的正向钉子
   在这台机器上都是假绿。这一轮把发现降级的方式改成回调（`setUiDegradedListener`）不是口味问题，
   是"这条路测得了吗"先于"这条路优雅吗"。
6. **`(holder.children || []).find(...)` 又踩了一次**（仓库自己的老陷阱：`children` 是 HTMLCollection，
   没有 `.find`）。改用了仓内已有的 `kids()` 助手。
7. **`applyUiMode` 在 boot 时就把台面重画了一遍**，而那时没有 notebook——`renderThread()` 白跑且碰到
   尚未初始化的台面账。加一句 `if (state.notebook)`。
8. 加了 `ui_shapes` 这个新消息类型又**回滚**了（§2 那条判决）。留下这条记录是因为：
   "服务端零改动"不是省事的结论，是试着改了、发现要维护两份账之后退回来的结论。

## 6. 有意没学 OpenAI 的那几处

抄来的（机制层面）：边生成边编译（宿主本来就有）、界面是模型输出的一部分而不是另起的产物、
一个用户侧的"只要文字"开关、以及"训练目标里包含**什么时候一段纯文字就够了**"这一手——
在本仓它不是训练目标而是**词汇表 + 提示 + 可读回的反馈**三件东西。

刻意不抄的（每条都对着本仓某条不变量）：

| OpenAI 那一手 | 本仓的选择 | 为什么不抄 |
| --- | --- | --- |
| 约 70 个原生组件、界面由模型撰写 | 封闭四档，词表外一律退回原文 | 封闭才谈得上机械校验；自由生成造得出"看着像官方控件"的假控件，而 Invariant 4 第③条要的就是"判分不进控件"这种可对照的形状 |
| 学情侧可视化（进度、百分比一类） | 明名单九档永不做，话术说是"规定不是故障" | 违规指纹①；`ui-skeleton` 连一个数字都不许有 |
| 界面状态刷新还在、跨会话即清（"threads 是独立现实"） | **持久**：`ui:` 前缀落进 `artifact_state`，换会话按本子续 | 本仓契约是"凡产出具交互性的制品，其作答状态必须能被下一轮读到"。这里 OpenAI 的口径比我们的要求松 |
| 组件流式增量到达 | 同一件事，但 `partial` 内不判失败、只打一行围栏时不摆空块 | 逐 token 时 `kind: c` 是 `compare` 的前缀；报错要给犯过的那个错 |
| 用户端可读性与"视觉杂乱"的批评 | 只用已量过的 token、新增 22 条选择器规则、开关一键全关 | 那条批评的根因是模型自由排版；这一档把排版收在宿主样式里，`styles.css` 是唯一出处 |
| 提示注入面（模型生成的控件即攻击面） | 词汇表封闭 + 手写表达式词法（无 `eval` / `new Function`）+ 全量 HTML/属性位转义 + 不新开服务端写面 | 攻击面按"能被说出的话"计数比按"能被渲染的像素"计数靠谱得多 |

至于模型会不会真用这一档、以及会不会因此少写散文——faux 测不出教学体感，
这条只能请用户开一局看（与 2026-10-04 那条 ` ```dialogue ` 的收尾同一口径）。

## 7. 遗留（记在案）

- **`compare` / `steps` 没有回报**。静态形状没有"学习者在里面做过什么"这回事，所以不进
  `UI_STATEFUL`、不进 `artifact_state`。若以后要记"看过哪张对照表"，那是新 kinds 的新契约，
  不是这一档的缺漏——别顺手补。
- **一轮最多一个界面**目前只是提示侧的自律，宿主不拦：模型放三个也照编。要拦就得让编译器数
  整段正文的围栏数，而那是"渲染器替内容把关"，与本仓"制品只给现象，不判对错"的分工不同侧。
- **`calculator` 没有除法与括号**。想表达比例就得写成乘法（`单价 * 0.5`）；确实表达不了的
  （复合利息、分段函数）走 `share_artifact`。这是词法封闭的必然代价，记在这儿免得当成 bug 修。
- **界面开关只影响渲染，不影响已落盘的状态**。先勾了再切"只要文字"，那份 `done` 仍在盘上、
  仍会注入——这是设计如此（状态是事实，不是视图），但学习者看不出来，文案没提。
- 上轮遗留（config 字段级损坏、quarantine / jobs 目录不在体检内、uploads 记录与盘不一致、
  `topic/goal/learner` 无写通道、回合 epoch）维持原样。
