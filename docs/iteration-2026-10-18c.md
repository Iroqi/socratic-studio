### 排除项（每条都有实验/证据）

1. **CSS 结构**：大括号 561=561 平衡；`.layout` 列宽声明正常（216px + minmax(0,1fr)），无隐藏覆盖。
2. **第 40 轮改动范围**：`git show fffefe4` 确认改动全部在 rail 区域（rail-head/brand/rail-list/rail-search/rail-foot/nb-item/rename-card），**未触碰主区任何规则**。
3. **超宽内容撑宽**：注入 900px / 2000px 宽元素，`thread-inner`/`composer-wrap` 位置不变（`.thread` 的 `overflow-y:auto` 使 overflow-x 计算为 auto，内容溢出不撑宽）。
4. **`timeline-sep` 时间戳**：属既有设计，位置正常（thread-inner 内容左缘 511+2 CSS）。
5. **rail 宽度覆盖**：全文件 grep 无第二处 rail 宽度规则。

### 用户截图像素级分析

- 用户 rail 分割线 270px 物理 = 216 CSS × 1.25 → **用户环境 = 1454 CSS 视口 × 125% DPI 缩放**（rail 占视口比例 14.85% 与本地 14.86% 一致）。
- 1454 CSS 视口下的布局公式与本地 iframe 权威测量完全相同（同一份 CSS，视口 >1180 无 MQ 分支）——即用户浏览器内的 **CSS 布局本身应当与本地一致**。
- 但用户截图各元素偏移量彼此矛盾：拍号 +37、消息 +46、composer +103（且 composer 实测宽 896 ≠ 理论 980），status-strip/时间戳则基本正常。**单一"整体偏移"、单一"左栏加宽"、单一"视口差"均无法自洽解释** → 指向用户侧渲染环境因素（DPI 缩放组合 / 扩展注入 / 窗口状态）。

## 修复（防御性，第四十一轮）

无法在本地复现的确切组合，但横向滚动是"主区内容看起来整段偏右"的最常见真实机制；flex 链式撑宽是"居中参照偏移"的常见诱因。两项成本极低、零副作用：

```css
/* html, body */
overflow-x: hidden;   /* 任何比视口宽的隐性内容都不该把整页推成可横滚 */

/* 新增 */
.stage,
.thread,
.composer-wrap { min-width: 0; }   /* 杜绝 flex 链式撑宽，居中参照不被内容顶偏 */
```

### 验证

- 全量六套件 2667 项断言全绿（web-smoke 1197 项含第 40 轮 §1.1 外观检查）。
- 修复后真实浏览器重测：1280 / 1454 两视口 `.rail/.thread-inner/.composer-wrap/.beat` rect 与修复前逐像素一致，**零副作用**。
