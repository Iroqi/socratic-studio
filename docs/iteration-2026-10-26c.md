# 第四十九轮：窗口说明的诚实性——「一字未删都在笔记页」是假话，给可执行的写协议

> 日期：2026-10-26（用户本地，第三轮同日记 26c）
> 基线：`033c9d9`（第 48 轮，回读路径补全）
> 判决依据：第一性原理（承诺 ≤ 能力，否则模型会按假承诺行事）+ 实测审计（把假话钉成断言）+ 奥卡姆剃刀（零新增状态 / 工具 / UI，只改 prompt 与断言）

## 一手依据：第 48 轮修完「读笔记」，窗口说明里还剩半句假话

第四十六轮定下窗口 = 锚点（开头第一条） + 窗口外学习者亲口的话（至多 8 条，按时间序） + 最近一段，
总条数恒等于上限。第四十八轮让「读笔记」成为真实动作（get_learning_graph include=notes 带回全部
结构化笔记）。但窗口说明（对话 > 40 条才出现）当时还写着：

> 那些内容**一字未删**，都在「笔记」页与概念图谱里。需要回想早先说过的话时，用 get_learning_graph 读回……

拆成两半看：

- **「都在笔记页与概念图谱里」是假话**。学习者的自由输入（自述 / 解释 / 质疑）是结构化层不捕获的
  证据——第四十六轮自己的注释就写着「自由输入只有对话里有」（提问作答另有事件账本，自由输入没有）。
  笔记页装的是模型写下的结构化讲义，图谱装的是概念与进度；**窗口外第 9 条以后的学习者原话，盘上有、
  模型读不到**。而模型被这句假话教成「都在笔记里，先读笔记」——它以为读得到，其实读不到。
- **对策缺失**。模型手里明明有写路径（compile_notes 收知识点笔记、set_progress_state 的 session_note
  收记仇项、概念 note 收观察），prompt 却从没告诉它「学习者给出关键自述时要当场写下来」。
  等窗口把它丢掉，就真的丢了——「不要凭印象编造」和「凭印象编造」之间没有第四条路。

这就是第 46 / 48 轮契约对账家族的第三层：第一层是「作答有账本、自由输入没有」，第二层是
「承诺读笔记、工具读不到」，第三层是「窗口外的原话有上限、承诺却说都在」。

## Brainstorm：候选表与判决

| 候选 | 价值 | 成本 / 风险 | 判决 |
|---|---|---|---|
| **窗口说明诚实化 + 写协议**（本轮） | 高：同一家族再深一层；承诺比能力多，模型会按假承诺行事；把「丢原话」从不可防变成可防 | 低：只改 prompt 文案 + 断言，零新增状态 / 工具 / UI | **做** |
| 原话保全预算 8→N | 低：治标；牺牲最近段，固定点机制是刻意设计 | 中：窗口预算恒等是铁律 | 维持 |
| 自由输入全量账本 | 低：无界增长，违背「抗漂移靠缩短上下文」 | 高：新状态 + 新注入面 | 维持 |
| 窗口内原话去重（第 46 轮留待有场景） | 低–中：本轮场景（12 条原话 > 8 预算）出现了一半，但去重是另一个手术，先不动 | 中 | 维持 |
| 事件账本扩展（自由输入也进账本） | 中：与「盘上有」重叠，且同样要定上限 | 中 | 维持 |

**为什么是「说真话 + 给写协议」而不是「继续补读」**：自由输入进账本等于再造一个窗口
（还得定上限，问题原样搬一层）；把预算翻倍等于牺牲最近段。而模型手里已经有一把写工具——
缺口不是工具，是「prompt 没告诉它要写、也没告诉它写了才读得到」。这是奥卡姆意义上的
最小修复：承诺与能力对齐，且给了模型一条真实可行的保全路径。

## 方案

**prompt.mjs 窗口说明重写（窗口启用时才注入的那段），三件事一次说清：**

1. **窗口的事实**：只保留开头一句（学习起点）、最近一段，以及窗口外学习者亲口说过的话
   （至多 N 条，N = MAX_KEPT_LEARNER_MESSAGES，直接插值自 config——单一事实源，改预算
   不用改文案）。更早的讲解与讨论不在上下文里——**那些原话盘上有，但你读不到**。
2. **什么读得到 / 读不到**：你写进「笔记」页、概念图谱与进度备注的内容都读得到
   （get_learning_graph include=notes 或 all 带回全部结构化笔记）；窗口外的原话读不到。
   **不要凭印象编造学习者早先说过的话**（12e 四钉子原样保留）。
3. **写协议（对策）**：学习者说出关键自述 / 背景 / 约束 / 误解时，**当场写进结构层**——
   知识点用 compile_notes，观察与记仇用 set_progress_state 的 session_note 或概念 note。
   别等窗口把它丢掉，丢了你读不到，也不能装作记得。

同时删掉旧文案里「那些内容一字未删，都在「笔记」页与概念图谱里」这句假话。

## 验证

- **全量六套件 2854 项断言全绿**（`npm run test:all`：run 724 / runtime-unit 92 / contract 416 /
  web-smoke 1330 / http-smoke 249 / artifact-evidence 43；基线 2845，+9 为 12n 新增）。
- **变异三连（先红后恢复，还原后全量重跑全绿）**：
  1. **假话回魂**（把「都在「笔记」页与概念图谱里」加回窗口说明）→「不再承诺都在笔记页」当场失败；
  2. **上限漂移**（至多 N 条写死成 12）→「上限与 config 同源」当场失败；
  3. **砍写协议**（按行切变异，删「当场写进结构层…compile_notes」句）→「给写协议」当场失败。
  每次变异后还原，还原态 run.mjs 724 项全绿、test:all 2854 项全绿。
- **审计路上抓到一个假绿**：12n 初版断言直接查整份 prompt 的「至多 8 条」——question 档语法
  「option 至多 8 条」也在 prompt 里，变体 B（写死 12）竟然全绿。切块到「对话窗口说明」之后
  才真红。教训：断言要钉住对象（窗口说明块），不钉住就是第 17 轮警告过的假绿复发。
- **既有契约零漂移**：12e 四钉子（笔记 / 图谱 / 不要凭印象编造 / 学习者亲口说过的话）原样通过；
  12f（回读路径）与其余套件未受影响。
