Intelligent UI 设计迭代方案并进行迭代，直接在 main 提交并推送。
本轮从 IUI 里取的是官方博文「Learn complex topics more easily」那一节的旗舰用例——
**把复杂概念画出来**（中心极限定理一例：分布的形状一眼见底；周日烤肉一例：把时间线排成可读的
图）。本仓补上第七档 `chart`，但沿第二十六轮 diagram 的尺：**只借形状、不借交互**。

判决：补第七档 `chart`，**只借"画出来"这一手，不借"动起来"那一手**——图是静态的，
学习者对图的交互是对话（指着图问"如果更大呢"，模型下一轮再画一张）。所以它像 `compare` /
`steps` 一样：**没有 id、不进 `UI_STATEFUL`、不落 `artifact_state`、不写 data-\*、写
`handoff` 掉回原文**。服务端零改动、宿主零改动、`server/rules/` 一字未动。

## 3. 方案与实施

### 3.1 词汇表（`web/ui-compile.js`）

- 第七档 `chart`：`series: 名 = 数值,数值,…`（1–4 条，每条 2–40 个点）+ 可选
  `x: 标签,…`（数量与点数对齐）、`type: bar | line`（缺省 line）与 `title`。
- **数值只收一种形状**（`CHART_NUM`）：可负、可小数；千分位逗号、科学计数、空格一律不认——
  认了就是"1,000"被拆成两个点的**静默坏数据**，那比掉回原文糟（这条是硬判决：坏数据不许静默）。
- **身份是名字**：两条 series 重名掉回原文并点名；点数不对齐掉回原文（少一个点就少一截）。
- **几何是确定的**：同一份输入两次编译长得一模一样（流式每帧重编，坐标跳来跳去的图没法
  对着问为什么）。y 轴范围由数据 + 8% 内边距算出，柱状图让出半个组宽不压左轴。
- **降级路径逐条点名**：无 series / 单点 / 点数不对齐 / 重名 / 非数（含千分位陷阱）/
  x 标签对不上 / x 标签超长 / type 非法 / 误写 handoff / 超 40 点 / 超 4 条，全掉回原文。
- **读屏名只放"是什么、有哪些系列"**（`数据图：{标题}。折线图：收入、支出`），不塞数字——
  数据值在可见轴上，连 aria 也不出现数字（照 diagram 的尺：结构数量不是学情指标，
  但连 aria 里也不放，免得哪天"数字不许进界面"这条被读屏用户先看见）。
- 静态档 → 不进 `UI_STATEFUL`，`suggest` 仍是唯一的无状态档。

### 3.2 样式（`web/styles.css`，16 条）

- `.ui-chart`（surface-2 面板，照 `.ui-calc` 的语言）+ `.ui-chart-svg` + 轴/标签/图例一族。
- **系列色只借已量过的 token**：`--accent / --teal / --ink-2 / --ink` 四条，折线描边、
  柱体填充各用一份；轴与标签用 `--ink-3`（对 surface-2 实测 4.70:1）。零新十六进制。
- **图例色点不做成自造底色块**：§39 那条"块状底色只借 --surface-2"的机械账不许破——
  色点是 9px 方块，底仍是 surface-2，系列色只出现在**描边**上（图例映射靠描边，不靠填色）。

### 3.3 提示（`server/prompt.mjs`，只动 APP_ADAPTER）

- 词表六档升七档，加 `chart` 一行；硬规矩六条升七条：新第 7 条——**chart 画的是正在教的
  数据，不是学习者的学情**（趋势 / 分布 / 对比都行，但画的是温度 / 价格 / 人数这类对象本身
  的数据；进度、对错、掌握度是 Invariant 4 否决的一族，chart 里也不许装）。它和 diagram
  一样静态：没有可点可拖的东西，学习者对图的深问留在对话里。要柱状图写 `type: bar`——
  `kind: bar` 是被否决的档。
- 硬规矩 5 的静态档名单补上 `chart`（没有可交回的状态，写 handoff 掉回原文）。
- 「什么时候用」补两条：数据有形状（趋势 / 分布 / 对比）就用 chart，别用 compare 硬装
  （五六个时间点的走势是折线，两三个方案才是对照表）；系列名用短标识、数值只认数字。

## 4. 测试（web-smoke §45，29 项；contract 自动推导 +9）

- 编译：两系列折线长成两条 polyline、柱状长成 rect（2 系列 × 2 点 = 4 个）、title 成引导语、
  不写 type 缺省折线、x 标签照数量渲染、y 轴上下两个刻度、图例摆出系列名。
- 确定性：同一份输入两次编译一模一样。
- 降级：无 series / 单点 / 点数不对齐 / 重名 / 千分位陷阱 / 非数 / x 对不上 / type 非法 /
  误写 handoff / 超 40 点 / 超 4 条，逐条掉回原文并点名；`kind: bar` 仍被否决。
- Invariant 4：chart 不进 `UI_STATEFUL`、编译产物一个 data-\* 都不写、不发状态消息。
- 转义：标签里的引号 / 尖括号进属性要转义、不长出脚本；aria 只放标题与系列名、不塞数字。
- contract 零改动：`UI_KINDS` 加一档后，词表逐行点名、编译器函数、样式类覆盖自动长出 +9
  （334 → 343）。

## 5. 变异验证（8 枚，`/tmp/mut31.mjs`）

| 变异 | 动的手 | 结果 |
| --- | --- | --- |
| M1 | 拆掉"至少 2 个点"那道闸 | 红 |
| M2 | 拆掉"系列重名"那道闸 | 红 |
| M3 | 拆掉"数值只认数字"那道闸（千分位/非数静默放过） | 红 |
| M4 | 拆掉"x 标签数量对齐"那道闸 | 红 |
| M5 | 拆掉"chart 拒收 handoff"那道闸 | 红 |
| M6 | 拆掉"type 只认 bar/line"那道闸 | 红 |
| M7 | 拆掉"最多 40 个点"那道闸 | 红 |
| M8 | 系列类名不再按序号区分（全给 ui-series-0） | 红 |

驱动沿用上两轮教训：单行失效式变异，锚点先数出现次数（必须恰 1 次），补丁后文本必须
真变了再跑；每枚跑完从备份还原，最后核对工作树与 git diff 只剩正式改动。零假绿。

这轮变异驱动自己翻出两个坑（都是驱动 bug，不是被测代码的假绿）：
- **M5 的补丁搜索串打偏**：`if (pick(fields, 'handoff').length) {` 同时命中 `compileSuggest`
  与 `compileChart` 两处守卫，`replace()` 命中第一处（suggest），补丁根本没动到 chart 的
  守卫——第一版驱动靠"补丁后该有的没有"自检拦下了它，但该变异等于没跑。修法：锚点必须带
  chart 专属上下文（连消息原文一起锚），确认命中的是目标守卫。
- **M8 是替换型变异**：原针（`const cls = \`ui-series-${idx}\`;`）被整个换成新文本，
  "补丁后仍含原针"自然为假——拿它当"没动手"的证据是错的方向。修法：每枚变异配独立的
  verify（该有的要有、该没的要没），不再用统一的后缀推导。
