## 3. 方案与实施

### 3.1 跨本搜索（Iteration 1）

**服务端 `store.searchAllNotebooks(q, { cap=40, perNotebook=5 })`**：
- 空词/无命中回 `[]`；大小写不敏感。
- 逐本读盘扫：meta 标题/主题（kind=notebook）、chat 消息（kind=chat，摘上下文 36 字符）、
  notes（kind=note）、progress events（kind=event）、concepts（kind=concept）、
  artifacts manifest 标题（kind=artifact）。
- 每本最多 5 条、总量 40 条；有时间的按时间倒序（`bogus` 无时间戳的排后面）。
- 只读、不改状态、不建索引（本地工具，数据量可承受）。

**`GET /api/search?q=`**：serve.mjs 新路由，`q` 缺失兜成空词。

**前端**：
- `index.html`：左栏 rail-head 新增搜索框（type=search，aria-label）。
- `app.js`：`state.search = { q, results, timer }`；输入 300ms 防抖 → `runSearch()` →
  列表区换成搜索结果行（种类标签 + 标题 + 摘要）；点行 `openSearchHit` → 打开那本 +
  清搜索态；Esc/清空回普通列表。空词/无命中给一句人话。
- `__hooks` 挂 `renderNotebookList` / `runSearch` / `openSearchHit` / `KIND_LABEL`。

### 3.2 README 排查路由守护（Iteration 2）

`contract-consistency.mjs` 新增一节：
- 解析 README 全部 `/api/...` 引用（21 处，含 `$ID` / `<id>` / `<制品id>` / `<任意串>` / `:noteId`）。
- serve.mjs 路由清单 = 字面路由（`pathname === '/api/x'`）＋ 正则路由
  （`/^\/api\/notebooks\/([^/]+)\/turn$/` 的 `([^/]+)` / `(.+)` 捕获段）。
- 归一化：参数段统一写成 `:id`——README 的 `$ID` / `<…>` / `:x` 与 serve 正则的 `(...)`
  是同一种东西；查询串、末尾斜杠不算数。**关键坑**：`([^/]+)` 段里**含 `/`（字符类里的斜杠）**，
  不能 `split('/')` 再归一，只能整串替换。
- 逐个断言 README 引用在 serve.mjs 有真路由；同一路径重复出现只钉一次。

**新钉子逐条变异验证过（全部先红后恢复）：**
- 变异 A：`searchAllNotebooks` 对话扫描被禁 → run.mjs 12k-3 红。
- 变异 B：perNotebook 上限被删 → 12k-7 红（一个词占满一页压得住，是这条钉住的）。
- 变异 C：serve.mjs `/api/search` 改名 → http-smoke 16 全部红（标题/对话/无命中/空词/缺参数）。
- 变异 D：`openSearchHit` 不清搜索态 → web-smoke 34「点结果后搜索态清掉」「清态后列表回普通」红。
- 变异 E：README 塞一条假路由 `POST /api/notebooks/$ID/bogus-route` → contract-consistency
  「README 里写到的 … 在 serve.mjs 有真路由」红。守护真的能抓住"文档静默过期"。

**过程里修掉的两个真坑**：
1. **http-smoke 16 的对话命中**——初版复用第 2 节建的 `id` 本，但第 15 节故意写坏了它的
   chat.json 取证，搜索自然找不到消息。改成第 16 节自建新本、走一发真回合再搜，自包含。
2. **归一化的 split('/') 陷阱**——`([^/]+)` 段里含 `/`，先 split 再归一会被劈碎
   （`([^` / `]` / `+)/turn`），改成整串全局替换后 21 处引用一次全绿。
