# 第五十七轮：删掉「只要文字」开关——IUI 默认全开

> 日期：2026-10-28（用户本地，同日第五轮，档案名 28e）
> 基线：`52be735`（第 56 轮，用户实测两个 UI bug）
> 判决依据：用户直接指令「IUI 开关没必要 删了吧 默认就是启动就可以了 不需要这个开关」
> + 第一性原理（一个只有两个档位的全局开关，唯一作用是让"组件没渲染"多一种说不出原因的
> 形态；默认档就是 IUI，逃生口与降级报告功能重叠）+ 奥卡姆剃刀（删整条链路，不留
> localStorage 键、不留按钮、不留编译器门口的分支）

## 删了什么（一整条链路，不是把默认值改一下）

| 层 | 落点 | 动作 |
|---|---|---|
| 外壳 | `web/index.html` `#uiToggle` 按钮 | 删除（含"界面档"注释） |
| 宿主 | `app.js` `UI_MODE_KEY` / `currentUiMode` / `applyUiMode` / boot 接线 / 导出表 | 全删 |
| 编译器 | `ui-compile.js` `uiMode` / `setUiMode` / `getUiMode` / `compileUiBlock` 的 plain 早退 | 全删 |
| 渲染器 | `markdown.js` `getUiMode` import + 默认信封的 plain 检查 | 全删（正文始终包 `.ui-text`） |
| 测试 | web-smoke §11（界面开关）/ §14（那颗开关）/ §40-8 / §41-8 四处 plain 断言 | 改写成"开关没了"钉 |

## 为什么这是删不是改

- **开关与降级报告功能重叠**：要"原文"的唯一正当理由是"这段编坏了"——那已经有降级
  报告（点名 + 原文）。"只要文字"是第二条、不带理由的出口，且**静默**（plain 模式不报
  降级），等于给"组件没渲染"留了一个说不出原因的洞——上一轮用户报的 bug 1 追问下去
  就是这类洞。
- **默认值本来就不是开关的事**：`uiMode='rich'` 是默认，localStorage 只在用户手动切过
  后写盘。删掉开关后，**老浏览器里遗留的 `socratic-ui-mode=plain` 也一并失效**——app.js
  不再读这个键，刷新后照样渲染 IUI（CDP 实测）。
- 词表 / 降级 / 状态回放都不动：删的是"第二档"，不是编译管线。

## 验证

- **全量六套件 2976 项断言全绿**（`npm run test:all`：run 754 / runtime-unit 92 /
  contract 429 / web-smoke 1409 / http 249 / artifact 43；基线 2983，-7：删旧断言 8、
  新钉 3 等净值）。
- **变异一对（先红后恢复）**：
  1. 在编译器门口复活 `getUiMode/setUiMode` + plain 早退 →「编译器门口没有
     getUiMode/setUiMode」当场红；
  2. 在 index.html 复活 `#uiToggle` →「index.html 不再有 #uiToggle」当场红。
- **真实浏览器 CDP**：页面 DOM 无 `#uiToggle`；打开带计算器（`每人 = 金额 ÷ 人数
  = 120 ÷ 3 = 40 元`）与清单的笔记本全部渲染；**先设 `localStorage['socratic-ui-mode']
  ='plain'` 再刷新，IUI 依旧渲染**（遗留偏好被无视——这就是"默认就是启动"）。
- **测试纪律修正**：删开关前，web-smoke §11 会 `setUiDegradedListener(null)` 摘掉降级
  监听器，防止后续节（§43/44 数"不自动发言 / 不落状态"）被合法降级事件污染计数——
  本轮保留这一纪律并注明理由（该报什么在上游已验过）。

## 已知边界

- 编辑器/只读场景没有"关掉 IUI"的按钮了——要原文看浏览器源码或降级报告，设计上
  不再提供静默逃生口。
- 历史档案（第 10/11/12 轮等）里对"只要文字"开关的记载保留原样——那是当时的事实，
  不改写历史。
