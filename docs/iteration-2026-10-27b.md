# 第五十一轮：可核对界面的证据纪律——assume/source 只写真，宿主不校验内容

> 日期：2026-10-27（用户本地，同日第二轮，档案名 27b）
> 基线：`5bd615b`（第 50 轮，可核对的界面：算式、代入、前提与来源）
> 判决依据：第一性原理（可核对要连"核对的材料"一起可核对）+ 边界审计（宿主只验条数字数、不验内容，真伪责任在模型）+ 奥卡姆剃刀（零新增状态 / 工具 / UI / 端点，只补契约纪律）

## 一手依据：第 50 轮治的病，换个姿势会复发

第五十轮把"结果可核对"做成了：`calculator` / `form` / `chart` 的算式与代入过程由宿主从同一份
公式表自动生成（这部分天生可信），并可带 `assume`（前提，≤3 条、每条 ≤80 字）与 `source`
（来源与口径，≤120 字）。编译侧挡板封死了**形状**（只配三档、超条数超字数掉回原文）——
但 `assume` / `source` 的**内容**是模型写的话：

- 宿主只校验条数与字数，**不校验内容**（这是对的：宿主没法替模型担保真伪）；
- 而 prompt 的第十五条硬规矩只写了"它们只摆事实，不写判词"，**没有写"内容不许编造、拿不准就省略"**。

于是"可核对"少了一半：算式能核对，前提与来源不能。最坏情形——模型给结果挂一个编造的
"口径"或"出处"，学习者看到 `source: 2025 年统计年鉴` 只会更信，不会去核——**界面越像
官方控件，错答案越难被发现**，这正是第 50 轮开篇要治的病；没补纪律，它换个姿势复发。

**为什么是"补纪律"而不是"加校验"**：assume/source 的真伪只有模型知道（它刚讲过什么、
上下文里有什么），宿主没有判据来源，强行校验只能验形状。补契约纪律是唯一诚实且有效的面——
把"责任在模型"说破，把"省略"设为正当出口，把"经得起追问"绑成写的前提条件。

## 方案

**prompt.mjs 第十五条硬规矩补一段纪律（顺带用法条目补一行）：**

1. **责任划线**：`assume 与 source 的内容真伪是你的责任`——宿主只校验条数与字数、不校验内容。
2. **真实约束**：前提只写本回合上下文里**真实出现过的**约定（学习者确认过、或你刚讲过的事实）；
   来源只写**真出处**（教材 / 文档 / 对话里给过的数据）。
3. **省略出口**：拿不准就省略。
4. **核对义务**：它们会被学习者追问（"这个口径哪来的？"），写了就要经得起学习者追问——
   **宁可没来源，不写假来源**。
5. 用法条目（「什么时候用，什么时候别用」）：`assume / source 会被学习者追问——只写本回合里
   真实出现过的前提与真出处，拿不准就省略`。
