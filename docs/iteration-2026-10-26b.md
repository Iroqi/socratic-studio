# 第四十八轮：回读路径补全——契约承诺的「读笔记」机制必须真实存在

> 日期：2026-10-26（用户本地）
> 基线：`fd66093`（第 46 轮，对话窗口证据保全）；与第 47 轮 `map` 档同日并行，远端先落，rebase 收编为本轮
> 判决依据：第一性原理（承诺过的回想路径必须可执行）+ 实测审计（先证伪再动手）+ 奥卡姆剃刀（复用现有工具，不新增工具面）

## 一手依据：第 46 轮自己的前提是半句假话

第四十六轮让「讲解轮让位」的依据是：**结构状态在图谱/笔记里，模型读得到**。审计把这句话拆成两半：

- **图谱半句是真的**：模型有 `get_learning_graph`，Graph / 进度 / 补丁日志都读得到。
- **笔记半句是假的**：模型唯一能读的 `get_learning_graph` **并不带结构化笔记**。结构化笔记
  （`compile_notes` 收的那份：title / summary / key_points / example / concepts）只通过
  状态快照被动注入**最近 10 条**（`handout.slice(-10)`，且只有 title + summary）。

而 prompt 的窗口说明却白纸黑字写着：「那些内容**一字未删**，都在「笔记」页与概念图谱里。
需要回想早先说过的话时，先读笔记/图谱，不要凭印象编造。」——**一句没有工具的承诺**：

1. **打底定义读不回**：长会话超过 10 条笔记后，最早收的笔记（往往是打底定义、前置概念）
   既不在快照里，也没有任何工具能读回。模型讲后面的内容时，对早先约定过的措辞只能凭印象。
2. **要点/例子永远读不到**：快照只给 title + summary；key_points、example 对所有笔记都不可达。
   模型无法核对「这个点是不是已经收过一条笔记」——重复收笔记的风险随会话变长而放大
   （README 自己就警告过「它会按自己记忆里的旧版又收一条」）。
3. **承诺与能力漂移**：prompt 让模型「先读笔记」，模型却没有任何「读笔记」动作可做。
   契约层欠的账，最后都会变成模型浪费一步、或者干脆编造。

**为什么是「补承诺」而不是「砍承诺」**：两条路都诚实，但砍承诺（改成「笔记页是给学习者看的，
不在你的上下文里」）会让模型**真的**丢掉打底定义——那是第 46 轮刚治好的病的复发。
补承诺（让「读笔记」成为真实动作）是契约层收敛：把已经在承诺的话，变成已经存在的工具。

## 方案

**复用现有回想工具，零新增工具面：**

- `get_learning_graph` 的 `include` 新增 `notes` 值，并加入 `all`（模型默认路径不落下）：
  `out.handout = 全部结构化笔记`（id / title / summary / key_points / example / concepts /
  **edited_by**〔学生改过〕出处戳 / createdAt）。一条不多、一条不少——「读笔记页」的语义
  就是「整页都读得到」，不做截断（被动快照继续只给最近 10 条做日常注入；主动回读给全量，
  由模型自己决定何时用）。
- 工具描述更新：明说「include=notes（或 all）会把学生「笔记」页上**全部**结构化笔记带回」。
- 窗口说明把「先读笔记/图谱」落成真机制：点名 `get_learning_graph`（include=notes 或 all）。
  「笔记 / 图谱 / 不要凭印象编造 / 学习者亲口说过的话」四个 12e 钉子原样保留。
- 快照不动：被动注入最近 10 条是日常视图（当下学什么最重要），主动回读是全量
  （要回想才用）。两个机制各司其职，不做重叠扩张。

## 验证

- **全量六套件 2766 项断言全绿**（`npm run test:all`：run 715 / runtime-unit 92 / contract 403 /
  web-smoke 1264 / http-smoke 249 / artifact-evidence 43；基线 2756，+10 为 12f 新增）。
- **变异三连（先红后恢复，还原后全量重跑全绿）**：
  1. 删掉 notes 分支（include 条件改永不匹配）→ 「include=notes 带回全部」「打底定义在回读里」
     「key_points 比快照全」「〔学生改过〕戳跟着走」「include=all 同样带回」当场失败（5 项）；
  2. `edited_by` 一律 null → 「〔学生改过〕的出处戳跟着走」当场失败；
  3. notes 只认 `include==='notes'`、不进 `all` → 「include=all 同样带回全部笔记」当场失败。
- **既有契约零漂移**：contract-consistency 403 项通过（规则 ↔ 运行时对账未受影响）；
  12e 的 prompt 四钉子（笔记/图谱/不要凭印象编造/学习者亲口说过的话）原样通过。
- **审计路上的弯路**：execGetGraph 是 async——初版 12f 直接调用拿到的是 Promise，5 项当场红。
  定位（分支内调试确认代码路径正确）后给调用补 await，实现本身零改动。记录在此，教训是
  「对着 async 函数直接调，先看是不是 Promise」。
