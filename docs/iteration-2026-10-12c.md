## 3. 方案与实施（`web/app.js` 两个函数，测试一个节）

### 3.1 `renderUiStatePanel(body)`（回看卡本体）

- 筛子与 `hydrateUiState` **同一条**：`key.startsWith(UI_PREFIX) && s && typeof s === 'object' &&
  UI_STATEFUL.includes(s.uiKind)`——前缀 + 三档，一条都不多。
- 卡容器 `.ui-state-card`（无专属样式，纯分组）；标题复用 `.panel-section-title`（"这局动过的界面"），
  行复用 `.state-note`。
- 三档分支：
  - checklist：已勾原文逐行 `· ✓ ${原文}`（键是原文不是序号）；空勾显示"· 还没勾"。
  - calculator：参数与值逐行 `· ${参数} = ${值}`（跳过 `uiKind`）。
  - diagram：`· 看过：甲、乙` + `· 现在停在：X`；没点过显示"· 还没点过"。
- `fit(s)`：超过 40 字的原文截到 39 字加 `…`（卡不许被一条超长原文撑爆，完整内容在对话里）。
- 接线：`renderLearnPanel` 里插在 `renderRetestCard` 之后、`renderGraphPanel` 之前。

## 4. 变异验证（5 枚，`/tmp/mut28.mjs`，全红零假绿）

| 变异 | 动的手 | 结果 |
| --- | --- | --- |
| M1 | 去掉 `ui:` 前缀筛子 | 红（974/1） |
| M2 | 去掉 `UI_STATEFUL` 筛子 | 红（973/2） |
| M3 | 从面板里摘掉这张卡 | 红（966/9） |
| M4 | 去掉长文本截断 | 红（974/1） |
| M5 | 去掉"还没勾"空态 | 红（974/1） |

**第一轮跑出 M1/M2 假绿，根因是测试写了错误的谓词，不是实现没被变异打中**：

- M1 手动应用并确认变异文本在场后 §42 仍全绿——去掉前缀筛子后 `key.slice(UI_PREFIX.length)`
  把 `game-1` 切成 `-1`，而 §42 第 2 类断言 `!t42b.includes('game-1')` 找的是键名；`Array.includes`
  是**元素全等**不是子串匹配，`'清单「game-1」' !== 'game-1'` 恒为假，断言恒绿——检查找的是
  **错误的 bug 签名**（bug 长成 `-1`，检查却找 `game-1`）。
- M2 同理：`!t42b.includes('compare')` 对元素 `'compare「cmp1」'` 恒为假。
- 修复：前缀筛子断言改成**整卡内容全等**（长度 2 + 恰好 `清单「ok1」`/`· ✓ 甲`，变异后多出的
  `清单「-1」` 行立刻显形）；stateful 筛子断言改成 **join 后子串** `!t42b.join(' ').includes('compare')`。
- 教训（第三回）：变异要先确认自己动了手、再数红；断言要找 **bug 实际长成的签名**，不是
  "我以为会怎样"的签名。这轮额外一层：`Array.includes` 的语义陷阱（全等 vs 子串）。
- 调试工具链教训：`/tmp/ws-dbg.mjs` 用 `import.meta.url` 相对路径会解析错 `webDir`（`/tmp/../web`
  不存在）；副本必须放仓库 `test/` 内（`test/web-smoke-dbg.mjs`），dump 点放在 `renderPanel()`
  之后才抓得到内容。

## 5. 测试桩三个坑（本轮新增两个）
